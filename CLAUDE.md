# Loner

ARPG de celular (sempre **deitado**) e PC: o jogador anda com o herói (sempre manual), ataca pelo botão de ataque (no máximo a cada 2 s, segurar repete), usa as habilidades, troca itens e sobe de nível. Classes: **Arqueiro** (veneno, ataca de longe e recua), **Guerreiro** (sangramento, corpo a corpo com espada de uma mão, +40% de vida, mais armadura, 15% menos dano recebido e 1,5% de roubo de vida inato) e **Mago** (fogo/queimadura, ataca de longe com explosões em área, 8% menos vida). Página estática, **sem build e sem módulos**: `index.html` + `css/estilo.css` + `js/01..10`. Textos do jogo em português do Brasil.

- Site: GitHub Pages do repositório `lohnner/Loner` → https://lohnner.github.io/Loner/ (este jogo substituiu o antigo Loner de caminhão).
- Backend: Firebase, projeto **`loner-hq`** (login Google + Firestore). O projeto é **dividido com o jogo Loner** (caminhões) — ver regras abaixo.
- O Git não está instalado no PC do dono: a publicação é feita enviando os arquivos pelo site do GitHub (Add file › Upload files).

## Regras importantes

### Como os arquivos se enxergam (quem pode chamar o quê)
- São scripts clássicos carregados **em ordem** pelo `index.html`. Tudo que um arquivo declara no topo (`const`, `let`, `function`) fica visível para os outros (escopo global compartilhado). **Não use `import/export`** nem envolva arquivo em `(() => {...})()`.
- **Código que roda na hora em que o arquivo carrega** (fora de funções) só pode usar o que veio de arquivos **anteriores**. Ex.: `02-modelos.js` faz `let ST = calcStats()` e pode usar `S` do 01, mas não algo do 03.
- **Dentro de funções** pode chamar qualquer arquivo, porque elas só rodam depois que tudo carregou (ex.: `gainXp()` no 04 chama `dirtyPanel()` do 08).
- Arquivo novo: crie `js/NN-nome.js` com `'use strict';`, coloque o `<script>` no lugar certo do `index.html` e atualize esta tabela.
- Nomes globais são compartilhados: antes de criar um nome no topo, procure se já existe (`Grep`). Nunca use `window`, `document`, `location` ou `top` como nome.
- Botões chamam ações por `data-act="nome"` + `data-v="valor"` → função `ACT.nome(v)` em `08-hud.js`. Painel aberto redesenha com `dirtyPanel()`.

### Online / "multiplayer" (Firebase)
- **Login Google é obrigatório.** Fluxo: tela `#login` → "Entrar com Google" → **tela de personagens** (lista da conta com Jogar/Apagar, "Criar novo personagem", até `MAX_CHARS` = 5) → jogo. `accountReady` só fica `true` com um personagem em jogo; fora disso `save()` não faz nada (evita gravar estado vazio por cima da conta). Não mude essa proteção.
- Conta: `acct = {chars: [personagem, ...], stash: [itens], orbs: {orbes no armazém}, stashX, cos: [visuais], rv, savedAt}` (`toAcct()` precisa manter cada campo novo da conta). Cada personagem é um estado `S` completo com id `S.cid` (`'c' + dígitos`). `save()` → `accountStore()` coloca o `S` atual em `acct.chars` (pelo `cid`), grava a cópia local `localStorage['cacada-vibora-v1:' + uid]` e marca a nuvem. `accountTick()` envia `acct` inteiro como texto JSON para `viboraSaves/{uid}.data` no máximo a cada 20 s; `cloudFlush()` envia na hora (sair da aba, trocar de personagem, sair da conta, apagar).
- No login vale a versão mais nova (`savedAt`) entre nuvem e cópia local. `toAcct()` aceita o formato antigo (um personagem só) e mantém o `stash`. O save antigo sem conta (`localStorage['cacada-vibora-v1']`) vira um personagem da conta no primeiro login e é apagado.
- Ranking: tela cheia, com duas abas principais: **Nível** e **Masmorra** (`rankCls = 'dun'`, `orderBy('dun','desc')`, campo `dun` = melhor fase concluída, só enviado quando > 0 e permitido no `firestore.rules`). Dentro de Nível: aba **Geral** (todas as classes, `rankCls = 'geral'`, `orderBy('score','desc').limit(RANK_N)`, índice simples automático) e abas por classe (busca `where('cls','==',classe)` e ordena no navegador, sem índice composto). **Uma linha por personagem** em `ranking/{uid}_{cid}` com `{name, lv, par, score, cls, build, kills, updated}`; `score = lv + par + fração da barra de XP`. Enviado ao jogar, ao subir de nível/Paragon e a cada 60 s se mudou. Apagar o personagem apaga a linha dele. Só o nome do herói é público; nome/e-mail do Google nunca vão para o ranking.
- Erro `permission-denied` ao carregar = as regras publicadas no Console estão desatualizadas (falta `viboraSaves` ou o formato novo de `ranking`). A solução é publicar o `firestore.rules` desta pasta.
- **Todo texto vindo do Firestore passa por `esc()` antes de ir para `innerHTML`.**
- Só `09-conta.js` fala com o Firebase. Outros arquivos usam as funções dele.
- **`firestore.rules` contém as regras do jogo Loner (players, progress, messages, playerCalls...). Nunca apague nem substitua essas partes.** Para uma coleção nova, adicione um `match` novo **antes** do bloco final `match /{document=**}` (que bloqueia todo o resto). Se mudar os campos de `ranking` ou `viboraSaves`, atualize o `hasOnly([...])` e as validações. Depois de editar, o dono precisa colar o arquivo em Console Firebase › Firestore › Regras › Publicar.
- Domínios autorizados no login: `localhost`, `lohnner.github.io` (Authentication › Configurações).
- **Login no app (APK) e `authDomain`:** no site publicado o `authDomain` é `lohnner.github.io` (`SITE_HOST`); em outros endereços (localhost) continua `loner-hq.firebaseapp.com`. Os arquivos de login do Firebase ficam na pasta `raiz-lohnner.github.io/` deste projeto e são publicados no repositório **`lohnner/lohnner.github.io`** (o mesmo do `assetlinks.json`): `.nojekyll`, `__/auth/handler.html`, `handler.js`, `experiments.js`, `iframe.html`, `iframe.js` e `__/firebase/init.json` (cópias de `https://loner-hq.firebaseapp.com/__/auth/...`; `.html` porque o GitHub Pages serve `/handler` a partir de `handler.html`). No Google Cloud (projeto loner-hq › APIs e serviços › Credenciais › cliente OAuth Web) precisa estar `https://lohnner.github.io/__/auth/handler` em "URIs de redirecionamento autorizados". Dentro do app (`inApp()`: aberto pelo APK — `document.referrer` `android-app://`, guardado no `sessionStorage` — ou instalado em tela cheia) o login sai por `signInWithRedirect`, porque a janela (popup) não devolve o resultado na TWA; no navegador continua por popup. Se o Firebase atualizar o SDK e o login quebrar, baixe de novo esses arquivos.

### Classes, itens e balanceamento
- Cada classe tem 4 ativas e 5 passivas em `CLASS_KIT`; `setClass()` troca `ACTIVE/PASSIVE` ao entrar com o personagem (`playChar`) e a barra é refeita com `buildSkillbar()`. As teclas 1–4 seguem `ACTIVE`. Com o mouse sobre uma criatura, Flecha Venenosa, Explosão de Praga e Bola de Fogo vão nela.
- Rank máximo das habilidades: 7 (`SK_MAX`; Contágio/Sede de Sangue/Combustão 5). `normalize()` corta ranks acima e o resto vira ponto livre. Pontos podem ser gastos em qualquer lugar; redistribuir tudo só na vila.
- O espaço da arma continua com a chave `'bow'` (compatibilidade); o nome mostrado vem de `SLOT_N.bow` / `itemSlotN()`.
- Os atributos `pois`/`pdur` (itens, passivas, Paragon) valem para o dano ao longo do tempo da classe: veneno no Arqueiro, sangramento no Guerreiro, queimadura no Mago. Textos usam `dotN()`/`dotT()`/`dotDe()` (`DOT_INFO`). Classe nova: entrada em `SKD`, `CLASS_KIT`, `DOT_INFO`, `WEAPONS`/`WEAPON_N`/`WEAPON_ICON`, `CLASSES`, `BUILDS`, `startWeapon`, `calcStats` (passivas e dps), `skDesc`, `manualCast/doSkill`, ícones, `drawHero` e `DEF_NAME`.
- Sangramento dói 50% mais enquanto o monstro anda (`monUpdate`).
- **Só 4 tipos de dano** (`ELEM` em 01): **Fogo** `fire`, **Raio** `light`, **Gelo** `cold`, **Veneno** `poison` (não existe mais físico, caos, necrótico nem psíquico). Toda criatura causa um deles: `MON_EL` (01) por mapa — Campos Raio+Veneno, Floresta Gelo+Veneno, Pântano só Veneno, Mina Fogo+Raio, Catacumbas Gelo+Veneno, Picos Gelo+Raio, Deserto Fogo+Veneno, Cidadela Raio+Gelo, Abismo só Fogo; vira `MONS[k].el` e a cor do tiro (`ranged`) acompanha. Em `hurtHero()` (04) todo dano é reduzido pela armadura (inteira) e por `ST.res[tipo]` (máx. `RES_MAX` = 75%). Resistências: afixos `rf rl rc rp` e `rall` (todos os 4), em `calcStats()` (02); inatas: Arqueiro +20% veneno, Mago +20% fogo. Painel do Herói mostra as 4 resistências; o de Mapas mostra os tipos de dano do mapa (com a sua resistência) e de cada criatura. Saves com `ver < 5` (armazém antigo com `rv < 5`) passam por `migrateElemItem()` (01): cada resistência antiga (`OLD_RES` = rx, rn, rs) vira uma das 4 que o item ainda não tem (ou `rall`), mantendo a qualidade `t`.
- Ultimates: Explosão de Praga (Arqueiro) é uma flecha que explode na criatura atingida (`plagueBurst`, raio `BURST_R` = 170); Ruptura (Guerreiro) e Inferno (Mago) explodem em volta do herói. A Investida (Guerreiro) termina com uma explosão pequena (`dashBoom`, raio `DASH_BOOM_R` = 65, em 06).
- Raridades (`RAR` em 01, cores também em `--r0..--r4` no CSS): Comum (branco, 0 atributos), Incomum (verde, 1), Raro (azul, 2), Épico (roxo, 3), Lendário (amarelo, 4 + a +habilidade da classe, `LEG_R` = 4). O número de atributos é `AFF_N[rar]`; a força da base/atributos é `RAR_F` (02). `--perf` (laranja) é a cor do ◆ "atributo perto do máximo". Saves com `ver < 3` (e armazém sem `acct.rv`) passam por `migrateItem()`: o antigo Lendário (3) vira 4 e Mágico/Raro viram a raridade do número de atributos.
- Nível exigido dos itens: `reqLv(it)` = ilvl − 3 (Comum), −2 (Incomum e Raro), −1 (Épico), ilvl (Lendário), entre 1 e 40. É calculado (não fica salvo), então vale para itens antigos. Equipar exige `canEquip()` (classe certa e nível).
- Itens: armas e lendários com +habilidade têm `it.cls`; só a classe certa equipa (`canUse()`). 25% dos drops saem para outra classe; o mercador vende só da sua classe.
- Orbes (`ORBS` em 01, chance própria em qualquer criatura): um por melhoria — **Despertar** `desp` (5%, Comum → Incomum), **Ascensão** `asc` (2,5%, → Raro), **Exaltação** `exa` (1%, → Épico), **Lenda** `lenda` (0,3%, → Lendário, ganha a +habilidade) — e a **Anulação** `anul` (1,5%, `rm`), que tira 1 atributo aleatório e baixa 1 raridade (num Lendário tira também a +habilidade). `ORBS[k].ok(it)` diz em quais itens serve. Ícone: os de melhoria são redondos com um redemoinho de energia dentro (`ICON_ORB`; no chão esfera de raio 7 com o redemoinho girando); a Anulação é um cristal partido ao meio (`ICON_ANUL`, `orbIcon(k)` em 08; no chão `drawAnulShard` em 07, escala .78). Os dois têm a mesma altura — mantenha assim ao mexer. Ficam em `S.orbs` (por personagem), na **aba Orbes da mochila**: um espaço fixo por tipo, sem limite de quantidade e sem ocupar os espaços de itens (`canPick` sempre pega orbe). Use sempre `invUsed()`/`invFull()` para espaço de itens. Uso em `upgradeItem()` (02; sobe/desce a base pela razão de `RAR_F`); drop no chão tem `d.orb` em vez de `d.it` (`canPick`, `drawOrbDrop`). Orbe novo: entrada em `ORBS` e no `orbs` de `defaults()`.
- Mochila (`panelBag`, duas abas `bagTab`: **Itens** e **Orbes**): `invMax()` = `INV_BASE` (10) + `S.invX` (espaços comprados, até `INV_CAP` = 20, preço `invSlotPrice()` = 5 mil, 10 mil, 15 mil... +5 mil a cada). Compra só na vila (`slotBuyBtn`, ação `buyInvSlot`). `invUsed()` = só itens. Nunca use número fixo de espaços. Itens além do limite aparecem em vermelho e o herói não pega mais itens até liberar espaço.
- **Não existe mais armazém.** `emptyOldStash()` (09, no `playChar`) leva o que sobrou do armazém antigo (`acct.stash`, `acct.orbs`) para a mochila do primeiro personagem que entrar e devolve o ouro dos espaços comprados (`acct.stashX`, preço antigo `stashSlotPrice`). O prédio virou o celeiro (só enfeite).
- Visuais (`COS`/`COS_T` em 01; tipos skin, trail, fx, name): saem do **Baú de Visuais** (`COS_CHEST` = 50 mil, no painel do Mercador, `chestHTML()`/`buyChest`), que sorteia um que a conta não tem. Os comprados ficam em `acct.cos` (da conta, `cosOwned()` em 09); o equipado é por personagem em `S.look` (troca no painel do Herói, `lookHTML()`, `<select data-look>` → `ACT.look`). `lookOf(t)` dá o visual equipado. Aplicação: roupa em `heroCloak()` (07), rastro em `heroTimers` (06), cor dos ataques em `fxLook()` (projéteis, golpe e giro do Guerreiro, 07), cor do nome na HUD (`updateHud`), em cima do herói (`drawBars`) e na lista de personagens. A cor do nome **não** vai para o ranking (precisaria mudar as regras do Firestore).
- Forja tem duas abas (`forgeTab` em 08): **Itens** (`forgeItemsHTML`) e **Orbes** (`forgeOrbsHTML`, ação `orbUp`): `ORB_UP_N` (10) orbes iguais viram 1 do próximo em `ORB_UP` (01): Despertar → Ascensão → Exaltação → Lenda (a Anulação não entra). Grátis, só na vila; `orbUpBlock()` checa mochila cheia.
- Custo da forja: `forgeCost(list)` (02) = (50 + maior ilvl × 25) × [1,2,4,8,16][maior raridade].
- Criaturas (07): desenhadas em pé, de lado, em "unidades de herói" escaladas por `r/13`, com os pés em `m.y + r*.6`. Cada `kind` tem sua função (`monBiped/monQuad/monSpider/monBlob`) e o detalhe de cada uma vem de `MON_DECO[tipo]` (chapéu, chifres, capuz, ossos, asas...). A barra de vida usa a altura `monH(m)`. Criatura nova: entrada em `MON_DECO` (e em `MON_H` se a altura for diferente do `kind`).
- Esquiva (`DODGE` em 01, por classe: Rolamento / Avanço / Teleporte): botão `#sb-dodge` à esquerda da barra (`buildSkillbar`), barra de espaço, ou dois toques rápidos no mapa no celular (`tapT` em 08; vai para onde o herói está andando). `doDodge(fromKey)` (04): vai para onde o jogador manda andar; com espaço sem WASD, para o mouse; senão, para longe da criatura mais perto. `hero.dodge` anda em `heroTimers` (06), `hero.invul` faz `hurtHero` ignorar o dano ("Esquivou"). Recarga em `cds.dodge` (reduzida pela recarga dos itens).
- Golpes em área das criaturas (`MON_AOE` em 01 → `MONS[k].aoe`; todas fora dos Campos de Trigo, além do ataque normal), cada um com um jeito (`k`) que combina com a criatura: **leap** (pula e cai na marca: lobos, cão, sapo, carniçal, gárgula, brutamonte — `m.leap`/`m.leapH`), **cone** (golpe à frente com abertura `spread`: cavaleiro, esqueleto, escorpião, cão — fica parada se preparando, `m.wind`), **slam** (pisão em volta dela: golem, sanguessuga), **bomb** (arremesso em arco até a marca: goblin, bruxa, yeti, aranha das cavernas — `z.bomb`), **spell** (magia embaixo do herói: ent, múmia, cultista, feiticeiro, ossudo, espírito). Recarga `AOE_CD` = 5 s; pronto e com o herói ao alcance (`reach`; **cone e pisão só encostados no herói**: alcance do ataque normal + raio + 6; visão livre), tenta a cada 1 s com `AOE_CHANCE` = 40% (`monUpdate`). `monAoe()` começa o golpe; depois de `AOE_T` = 0,7 s, `updateZones()` (06) acerta quem estiver dentro (`zoneHits`: círculo ou cone) com dano × `AOE_DMG` (2,5 — ser pego dói muito). Tiros das criaturas de longe a `MON_SHOT` = 380 px/s. Se a criatura morrer antes, pulo/cone/pisão não saem. Elites marcam 20% maior. Desenho das marcas, do cone e dos arremessos em `render()` (07).
- Forja da vila (botão `#tcForge` no cartão da vila → aba `forge`, `panelForge()` em 08, ações `forgeAdd/forgeDel/forge`, desenho em `drawTown`): 3 itens da mochila (`forgeSel`, ids) do mesmo tipo e da mesma raridade (`forgeMatch`: mesmo espaço e raridade; arma também da mesma classe, ex.: 3 arcos) viram 1 desse tipo na raridade acima, com status novos e o maior ilvl dos três (`forgeItems()` em 02; `forgeWhy()` diz o que falta). Lendário não sobe. Depois do 1º item a mochila da forja só mostra os que combinam. Só na vila.
- Masmorra (fim de jogo, `DUN`/`DUN_KILLS`/`DUN_STEP`/`dunMult()` em 01; estado `S.dun = {best, phase, kills, start}`): no nível 40 aparece o portal roxo na vila (`drawTown`) e o botão `#tcDun` → aba `dun` (`panelDun()`, ações `dunPhase/dunGo`). `enterDungeon(fase)` (03) entra no mapa `DUN` sem mudar `S.map`; `inDun()` diz se está lá. Criaturas de todos os mapas no nível 40, com vida e dano × 1,25^(fase−1) (`spawnPack`); XP também. `dunKill()` (04) conta 50 abates por fase, atualiza `best` (ranking) e passa de fase. Morrer, voltar para a vila ou trocar de mapa encerra a corrida (`enterTown`/`enterMap` zeram `phase`). A próxima pode começar em qualquer fase de 1 até `best + 1`.
- Paragon: cada nível dá +1 de dano na arma e +10 de vida (em `calcStats`), além do ponto para gastar.
- Velocidade do jogo: não existe mais (sempre 1x; `normalize` força `S.speed = 1`; `S.speed = 0` ainda pausa nos testes).
- **Vila** (andar sempre manual, mesmo com o automático ligado — o automático é só para os mapas): mundo `TOWN_W`×`TOWN_H`, prédios em `TOWN_B` (03: posição, tamanho, cores, `tab` do painel), `FOUNT`, `TPORT` (portal de saída), `DPORT` (Masmorra), `NPC_CHEST` (Tobias, vende o Baú de Visuais → aba `chest`, `panelChest`). `townBlocked()` = colisão; `townZones()` = portas (chegar perto abre o painel uma vez por visita). Movimento em `updateTown` (06) com `townMove()`: joystick/WASD (`manualDir` sempre vale na vila) ou tocar/clicar num ponto (`townTap` em 08 → `townGoal`; tocar num prédio anda até a porta). Cura em qualquer lugar da vila. Só existe o botão **Partir** (`#goBtn`, canto de cima à direita) — ou entrar no portal; longe dele, `depart()` abre um portal ao lado (`townExit`). Saída automática (Regras) só se o jogador não mexeu em nada desde que chegou (`townIdle`, `townLeaveIn()`). Venda em lote ficou no Mercador e na Mochila (`bulkSellHTML`).
- Desenho da vila (07): 3D em 3/4 — `drawBuilding()` (frente, lado direito, base de pedra, enxaimel, janelas acesas, porta, telhado de duas águas com empena, chaminé com fumaça; `stall`/`smithy`/`barn`/`tower` mudam detalhes), `drawFountain`, `drawTree`, `drawLamp`, `drawBarrel/Crate/Chest/Anvil`, `drawNPC`, `drawDunPortal`. Tudo com altura entra em `townProps()` e é ordenado por y junto com o herói em `render()`; chão em `drawTownGround()`, placas com nomes em `drawTownLabels()`.
- Mercador: raridade dos itens à venda em `shopRar()` (02): Comum 60%, Incomum 30%, Raro 7,5%, Épico 2%, Lendário 0,5%.
- Ao entrar com um personagem (`playChar`) o herói sempre começa na vila (`enterTown`), não no mapa.
- Controles: no celular, tocar e arrastar em qualquer lugar do canvas cria um joystick (`joy`, desenhado por `drawJoy()`); toque sem arrastar troca o alvo. **Multitoque**: o joystick e a barra de habilidades são dedos independentes (cada um pelo seu `pointerId`) — dá para andar e mirar/usar habilidade ao mesmo tempo. Na barra (08, `pointerdown` em `#skillbar`) as habilidades com mira começam a mirar no toque e lançam ao soltar; as outras e a esquiva saem no próprio toque (não dependem do `click`, que falha com outro dedo na tela; `skipClickT` evita repetir). Durante o lançamento (`hero.cast`) o herói continua andando a 70% se o joystick estiver em uso. No PC, WASD ou setas (`moveKeys`/`MOVE_KEY`). `manualDir()` em 05; eventos em 08.
- **Andar é sempre manual** (não existe mais IA de andar nem as opções "Andar manual"/"Voltar a caçar"): `heroAI` → `manualAI` (06) anda para `manualDir()` (joystick em qualquer lugar da tela no celular, WASD/setas no PC). Itens são pegos ao passar por cima.
- **Ataque normal manual** (04): botão grande `#sb-atk` (ícone da arma) ou, no PC, clicar/segurar o mouse no mapa. `basicAttack(angHint)` mira no alvo fixado ao alcance (`basicReach`), senão no mais perto ao alcance, senão para onde o herói olha (ou para o mouse); recarga `cds.atk` = `BASIC_CD` (2 s), golpe rápido `BASIC_DUR` (o herói para um instante). Segurar (`atkHeld`, por `pointerId`; `manualAI` tenta de novo a cada passo) repete quando a recarga acaba. Dano de cada golpe × `basicMult()` = `BASIC_CD` × velocidade de ataque × bônus do Titã, para o dano por segundo ficar igual ao do antigo ataque automático. Esquiva antes do golpe sair devolve a recarga. Nas simulações, use `atkHeld = {pid:-1}` para atacar sem parar.
- **Tela deitada** (CSS): `#app` e `#stage` ocupam a tela toda; HUD (`.hud`) e abas (`.nav`, só ícones) flutuam em cima à esquerda; minimapa, `#goBtn` e `#townBtn` (embaixo do minimapa) em cima à direita; o log embaixo da HUD. Botões em leque no canto de baixo à direita (`buildSkillbar`, 08): ataque no canto, as 4 ativas em arco (`SB_ARC`, raio `SB_R`), esquiva e suprema no arco de fora (`SB_R2`); cada um com `right/bottom` de `sbPos()`. O leque some na vila. Painéis (`#sheet`) e a janela do item ficam no meio da tela (fichas lado a lado em `.scards`). Celular em pé mostra `#rotate`; no navegador o 1º toque tenta tela cheia + `screen.orientation.lock('landscape')` (10); o `manifest.json` trava deitado no app. Na vila a câmera fica presa dentro da vila (`step`, 06). Voltar à vila por vida baixa ou mochila cheia (Regras) continua.
- **Mapas sempre aleatórios** (03): a cada `enterMap` `genLevel()` cria uma grade `LV_N`×`LV_N` (76×76) de ladrilhos `TILE` (40 px, paredes finas): 11–15 áreas grandes espalhadas com formato sorteado (retângulo, círculo, oval, caverna, **anel com ilha no meio** para dar a volta, uma arena grande, cruz), ligadas por árvore de menor caminho + 2–4 ligações extras (voltas), corredores curvos de largura 3 a 6 (anel: caminho `RING_W`); bordas suavizadas; o que ficar sem acesso vira parede. Início = área mais longe do meio (`LV.startPos`); `LV.dist` = distância pelo caminho a partir do início (criaturas nascem a ≥ 12). Obstáculos (`LV_SOLID`, `LV.g` = 2, `LV.sol` por ladrilho) só em ladrilho cercado de chão e nunca fechando passagem (confere com busca em largura); enfeites (`LV_DECO`). `LV.g`: 0 parede, 1 chão, 2 obstáculo. Colisão: `walkable(x, y, r)` (herói em `moveDir`, criaturas em `monStep`) — paredes por ladrilho; obstáculos **só pela base** (círculo `o.cr`, `SOLID_R` por tipo), então dá para passar atrás deles e eles ficam desenhados por cima; `rayEnd()` corta esquiva, Investida e avanços na parede; projéteis param na parede. Criaturas: `monChase()` vai reto se o corpo passa livre (`bodyPathClear`), senão segue a rota (`updateFlow()` = busca em largura a partir do herói; `monChaseAng` escolhe o vizinho em 8 direções sem cortar quina e mira 2 ladrilhos à frente) e, se travar 0,3 s, desvia para o lado livre (`m.detourT`). Só notam o herói perto pelo caminho (≤ 9 ladrilhos) e as de longe só atiram com visão livre (`losClear`).
- **Criaturas fixas por mapa**: `MAP_MONS` (80) por mapa (Masmorra: `DUN_KILLS`), espalhadas pelas salas por `spawnLevel()`; não nascem mais. Matou todas (`monsLeft()` = 0) → `mapCleared`, mensagem e o botão "Voltar à vila" brilha. Entrar de novo sorteia outro mapa.
- **Minimapa** (08, `#mmWrap`/`#mm`, `drawMinimap()` no `updateHud`): pequeno no canto de cima à direita, só com o que já foi visto (`LV.seen`, `markSeen()`); embaixo "Faltam N criaturas". Tocar abre grande (`minimapBig`, ação `mmToggle`) mostrando também as áreas não visitadas (vermelho). Criaturas só aparecem quando faltam `MM_SHOW` (10) ou menos.
- Heróis (07, em pé, de lado, luz de cima à esquerda; cores da roupa por `heroCloak()`): `heroLegs()` (joelho, bota com cano/sola; `knee`/`cuff`/`thick`). **Arqueiro** (veneno): capa que balança, aljava com flechas de ponta verde, túnica + colete de couro com alça, capuz com bico, rosto na sombra e lenço, arco recurvo com empunhadura, gota de veneno na flecha. **Guerreiro** (sangramento): capa, armadura de placas com reflexo, saia de cota de malha, tabardo com gota de sangue, ombreiras em camadas, elmo com viseira/respiros e pluma, espada longa com guarda, sulco e runas vermelhas pulsando. **Mago** (fogo): manto com barra dourada e runas acesas, faixa com gema, barba longa que balança, chapéu de aba larga com ponta torta, cajado retorcido com garras e cristal em chamas (as chamas sempre sobem). Só o herói usa degradês — mantém leve.
- Bordas dos mapas (07, preparadas em `prepLevel`): contorno irregular no pé das paredes (`BORDER_FRINGE`: mato, pedregulho, neve, areia; lava acesa no Abismo — desenhado num caminho só por camada), enfeites em cima das paredes (`BORDER_TOP`: árvores, pinheiros, pedras, cristais, túmulos…) e tochas acesas na face das paredes (`BORDER_TORCH`, `drawWallTorch`, brilho com círculos transparentes, sem degradê). Tudo entra na ordenação por y em `levelProps`. Medido: ~2–3 ms por quadro com 15 criaturas na tela.
- Desenho do mapa (07): `drawLevelFloor()` (padrão do chão só nas salas via `Path2D`, sombra das paredes, enfeites, cor do elemento na Masmorra) e `levelProps()` (paredes 3D com altura `WALL_H` e obstáculos entram na ordenação por y com o herói). Cores das paredes em `WALL_C`; campos/floresta/pântano usam mata (`WALL_LEAF`).
- **Supremas** (nível 40, sem pontos, tecla 5 / 5º botão dourado): `ULT` em 01 (Arqueiro `storm` Tempestade de Flechas, Guerreiro `titan` Fúria do Titã, Mago `cataclysm` Cataclismo), `SKD[id].ult`, `ultOf()`. `rk()` dá 1 sozinho no 40. Efeitos em `doUlt()` (04); bônus temporário do Titã em `hero.buff` / `heroBuff()` (dano em `dealHit`, velocidade de ataque em `basicMult`, roubo de vida). A barra usa `barSkills()`.
- Masmorra por elemento: `dunElem(fase)` (01) — `DUN_ELEMS` (fogo, gelo, raio, veneno), muda a cada `DUN_ELEM_SPAN` (5) fases e recomeça (fase 21 volta ao fogo). Toda criatura da fase recebe `m.el` (usado em `hurtHero`, zonas e projéteis) e tem aura dessa cor. Cada fase é um mapa novo de 50 criaturas; ao limpar, `dunKill` passa de fase e abre outro mapa em 2,5 s.
- Mapas (`MAPS`, nível mín–máx, libera 1 nível antes): Campos de Trigo 1–5, Floresta Sombria 5–11, Pântano Pútrido 12–16, Mina Abandonada 16–20, Catacumbas 20–24, Picos Gélidos 24–28, Deserto de Cinzas 28–32, Cidadela Profana 32–36, Abismo Ardente 36–40. Cada um tem **5 criaturas** em `MONS` (lista `mons`: as 3 primeiras com golpe em área em `MON_AOE`, as 2 últimas sem; desenho pelo `MON_DECO`, elemento em `MON_EL`) e um tipo de decoração (`decor`: field, forest, swamp, mine, crypt, ice, desert, citadel, hell) usado em `makeGround`/`makeDecor` (03) e `drawDecor`/`ROCK_C` (07). Mapa novo: entrada em `MAPS`, criaturas em `MONS` e, se for decoração nova, um caso em `makeDecor` e desenhos em `drawDecor`.
- Grupos: no `SOLO_MAP` (Campos de Trigo) as criaturas ficam sozinhas; nos outros mapas o grupo é sozinha 35% / dupla 30% / 3–5 35% (`packSize()`).
- Balanceamento (out/2026): força por raridade `RAR_F` = [1, 1, 1,06, 1,12, 1,22] (antes 1,08/1,18/1,35 — o Lendário dava +56% de dano sobre o Raro). Saves com `ver < 4` (e armazém com `acct.rv < 4`) passam por `rebalanceItem()` (02), que refaz base e atributos pela regra nova usando a qualidade `t` já sorteada. Simulação (grupos de 4 com elite a cada 3, jogador que recua/avança e desvia das áreas, todas as ativas): com equipamento Raro/Incomum do nível, cada grupo tira ~30–80% da vida (algumas mortes no Mago/Arqueiro); com Épico, bem menos. Ao mexer em números, rode de novo uma simulação parecida e compare as classes.

### Save e compatibilidade
- Campo novo no estado: coloque em `defaults()` (01-base). `normalize()` mistura o save antigo com os padrões, então saves antigos continuam funcionando. Não renomeie campos existentes de `S`.
- Nível máximo 40 (`MAX_LV`); depois a XP vira Paragon (`S.par`, `S.pxp`, pontos em `S.pp`).

## Como rodar e testar

`file://` não serve (o login Google não funciona). Rode um servidor local na pasta do jogo:

```bash
python -m http.server 4190 --bind 127.0.0.1 --directory "C:\Users\rodri\OneDrive\Documentos\Loner"
```

Abra http://localhost:4190 (`localhost` já está autorizado no Firebase). No Claude Code desktop, use `preview_start` com uma configuração no `.claude/launch.json` em vez de rodar o servidor pelo terminal. O navegador guarda os `.js` em cache: depois de editar, recarregue com `fetch(arquivo, {cache:'reload'})` em cada script ou Ctrl+F5.

Testando pelo console / `javascript_tool`:
- `window.__game` tem `S`, `ST`, `hero`, `ACT`, `step`, `render`, `updateHud`, `manualCast`. As funções globais também podem ser chamadas pelo nome (ex.: `accountTick(1)`, `cloudFlush()`, `gainXp(1000)`).
- Se o painel do navegador estiver escondido, o `requestAnimationFrame` para e o jogo congela. Avance na mão: `for(let i=0;i<500;i++) __game.step(.03); __game.updateHud();`.
- `S.speed = 0` pausa o jogo (é salvo no personagem: volte para 1 depois).
- Para testar login/save/ranking sem conta Google real, faça uma cópia da pasta num diretório temporário e troque os 3 `<script>` do firebasejs no `index.html` por um Firebase falso que guarda dados no `localStorage` (auth com `onAuthStateChanged/signInWithPopup/signOut` e `firestore().collection(n).doc(id).get/set/delete` + `where().orderBy().limit().get()`). Não teste escrevendo no Firestore real.
- Depois de qualquer mudança, confira: sem erros no console, tela de login aparece, mapa anda com `step`, todas as abas abrem (`ACT.tab('maps'|'hero'|'bag'|'rank'|'rules'|'shop'|'forge'|'chest')`), e as três classes jogam.
- Simulação de balanceamento: crie o personagem com `defaults(cls)` + `playChar()`, ponha `accountReady = false` (não salva), suba `S.lv`, distribua pontos, equipe `genItem(lv, 2, slot, cls)` em cada espaço, `S.cfg.ret = 0`, `enterMap(mapa)` e rode `step(.05)` em laço chamando `manualCast(id)` para cada ativa pronta. Meça `S.kills` por minuto, mortes (`mode === 'dead'`) e menor vida.
- Ao editar arquivos com PowerShell, não use listas aninhadas `@(@(a,b))` para trocas de texto: o PowerShell achata a lista e a troca vira caractere por caractere (já estragou este arquivo uma vez). Prefira a ferramenta de edição ou uma troca por vez.

## Publicar
- **Antes de publicar, aumente a versão `?v=N`** em todos os `<script src="js/...">` e no `<link href="css/estilo.css">` do `index.html` (todos com o mesmo número) **e coloque o mesmo N no `versao.json`**. Sem isso, o navegador dos jogadores pode misturar um arquivo novo com um antigo do cache e o jogo quebra (ex.: `stash is not defined`).
- Aviso de atualização (10): `GAME_V` vem do `?v=` do próprio `10-inicio.js`; ao abrir e ao voltar para o app (no máximo a cada `UPD_EVERY` = 5 min) `checkUpdate()` baixa o `versao.json` sem cache. Se o número for maior, a janela `#upd` (obrigatória) salva, envia a nuvem e abre `?u=N` (endereço novo = `index.html` novo), que depois é limpo da barra. Sem `?v=` numérico (cópia de teste) não confere.
- APK (Android): é uma TWA — o app só abre https://lohnner.github.io/Loner/ em tela cheia, então toda publicação no GitHub já atualiza quem tem o app (não precisa gerar outro APK). Gerado no PWABuilder (pwabuilder.com → URL do jogo → Android) com o site já publicado. **Guardar a chave de assinatura (`signing.keystore` + senhas) que vem no zip**: sem ela não dá para lançar versão nova do APK na Play Store. Para sumir a barra de endereço, o `assetlinks.json` do zip precisa ficar em `lohnner.github.io/.well-known/assetlinks.json` (repositório separado `lohnner/lohnner.github.io`).
- Enviar `index.html`, `versao.json`, `manifest.json`, `sw.js`, `icones/`, `css/`, `js/` (e `firestore.rules`, só como registro) para `lohnner/Loner` pelo site do GitHub; o Pages atualiza em 1–2 min. Se mudou `firestore.rules`, publicar também no Console do Firebase.
- O nome do jogo é **Loner**. Os identificadores internos antigos (`cacada-vibora-v1` no localStorage e a coleção `viboraSaves`) ficam como estão: trocar faria os saves sumirem.
